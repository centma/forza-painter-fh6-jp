> **本リポジトリについて:** [bvzrays/forza-painter-fh6](https://github.com/bvzrays/forza-painter-fh6) の派生版です。機能は派生元に準じ、日本語化とインターフェースの調整を行っています。アプリの既定言語は日本語です。

PNG/JPG/BMP 画像を Forza Horizon 6 のバイナルグループのレイヤーに変換します。生成・プレビュー・インポートを 1 つのデスクトップアプリで行えます。通常の利用では Python、`.venv`、バッチファイル、メモリアドレスの手入力は不要です。

> **EXE のダウンロード:** [Releases](https://github.com/bvzrays/forza-painter-fh6/releases) から `forza-painter-fh6-v1.9.7.exe` を入手し、そのまま実行します。

> **プリセットマーケット:** https://painter6.com またはアプリ内のマーケットバナーから、共有された画像・プリセット・JSON パッケージを閲覧できます。

> **結果がぼやける場合:** まず `ランダムサンプル数` を上げてください。**200000** を超えると品質が大きく向上することが多く、値を上げるほど鮮明になりますが生成時間は大幅に伸びます。

> **インポートには時間がかかることがあります:** v1.4.1 以降は複数の方法で FH6 テンプレートを探し、安全なレイヤーテーブルの検出に最大 5 分かかることがあります。FH6 をバイナルグループエディターのまま、メニューを切り替えずにお待ちください。それでも失敗する場合は詳細ログをエクスポートしてください。

## クイックスタート

1. [Releases](https://github.com/bvzrays/forza-painter-fh6/releases) から `forza-painter-fh6-v1.9.7.exe` をダウンロードします。
2. EXE を書き込み可能な通常のフォルダー (例: `Desktop\forza-painter-fh6`) に置きます。
3. EXE をダブルクリックします。FH6 へのインポート時に Windows がプロセスへのアクセスをブロックする場合は、管理者として実行してください。
4. FH6 で `バイナルグループの作成` / バイナルグループエディターを開き、球体テンプレートを読み込んで `グループ解除` します。
5. アプリで JSON を生成し、`インポート` ページを開いてテンプレートの正確なレイヤー数を入力し、インポートします。

プロジェクトを開発する場合を除き、GitHub が自動生成する `Source code` ZIP はダウンロードしないでください。通常は `.exe` だけで十分です。

## JSON 生成

1. `JSON 生成` ページを開きます。
2. `画像を追加` をクリックし、PNG/JPG/BMP 画像を選びます。
3. 品質プリセットを選びます。
4. 任意: `グラフィックカード` を選びます。`自動 (最適な GPU)` ではジェネレーターが選択します。ゲームを動かしている GPU を避けたい場合などは、特定のカードを指定できます。
5. 任意: 複数の画像をキューに入れた場合は `並列処理する画像数` を上げます。下の [並列処理](#並列処理) を参照してください。
6. 任意: `カスタム設定を使用` を有効にすると、出力レイヤー数、解像度、ランダムサンプル数、変異サンプル数を変更できます。
7. 下部に固定された `現在の設定で生成` ボタンをクリックします。
8. プレビューとログが更新されるのを待ちます。

生成した JSON とチェックポイントは、アプリと同じ場所の `out/<画像名>/<拡張子>/` に保存されます。生成に使った元画像は `image/<拡張子>/` にバックアップされます。例えば `logo.png` の出力は `out/logo/png/`、`logo.jpg` の出力は `out/logo/jpg/` に保存されます。

1 枚の画像から複数のチェックポイント JSON が生成されます。テンプレートに合う最もレイヤー数の多い JSON を使ってください。例えば 3000 レイヤーのテンプレートには `image.3000.json` または最終の `image.json` を使います。3000 レイヤーのテンプレートに 500 レイヤーの JSON をインポートすると、ぼやけた結果になります。

### 並列処理

ジェネレーターはシングルスレッドの CPU 処理 (候補シェイプの選出) と GPU 処理 (評価) を交互に行うため、1 枚だけの実行では各レイヤーの約 40% の時間 GPU が待機しています。複数の画像を同時に実行すると、その空き時間を埋められます。

| 並列処理する画像数 | スループット |
| ---: | --- |
| 1 | 基準 |
| 2 | 約 1.5 倍 |
| 3 | 約 1.9 倍 |

RX 9070 XT での計測値です。効果があるのは 2 枚以上をキューに入れた場合のみで、1 枚だけならどの設定でも所要時間は同じです。1 より大きい値では、レイヤー単位の残り時間の代わりに画像の完了数が表示され、各ログ行の先頭に画像名が付きます。並列ジョブはそれぞれ独立したジェネレーターのプロセスで、GPU 上に画像のコピーを持つため、`maxResolution` の高いプリセットでは VRAM 使用量に注意してください。

| プリセット | 出力レイヤー数 | ランダムサンプル数 | 用途 |
| --- | ---: | ---: | --- |
| extremely fast | 500 | 30000 | 構図の簡易確認 |
| fast | 1000 | 60000 | 使える下書きを素早く |
| balanced | 1800 | 120000 | 推奨の既定値 |
| slow | 2500 | 220000 | 最終品質。200k 以上の高品質域に入る |
| super slow | 3000 | 350000 | 最高の鮮明さ、非常に低速 |

## JSON インポート

1. FH6 を起動し、バイナルグループエディターを開いたままにします。
2. 多数のシンプルな球体レイヤーで構成されたテンプレートを読み込むか作成します。
3. テンプレートを `グループ解除` し、ゲーム内の正確なレイヤー数を控えます。
4. アプリで `インポート` を開き、`更新` をクリックして `forzahorizon6.exe` を選びます。
5. テンプレートの正確なレイヤー数を入力します。
6. 生成した `.json` を追加するか、`生成した JSON を使用` をクリックします。
7. 詳細オプションのアドレス欄は空のまま、`JSON をインポート` をクリックします。

FH でカバーと適用範囲を正しく保存するには、境界用に 4 レイヤー余分に必要です。例: 1000 レイヤーの JSON には 1004 レイヤー以上のテンプレートを使います。3000 レイヤーのテンプレートには描画シェイプを約 2996 個インポートできます。

## 実験的: フルシェイプ インポート/エクスポート

v1.8.1 では領域を絞って繰り返し描き込む「領域ペイント」タブを追加しました。v1.8.0 では FH6 の type-code JSON の研究用サポートをメインのワークフローに追加しました。フルシェイプ/type-code JSON は `インポート` ページからインポートし、編集中の FH6 グループは `エクスポート` ページからエクスポートします。

この機能はフルシェイプ JSON 専用です。通常の生成済み楕円 JSON は引き続き通常の `インポート` ページを使ってください。

- エクスポートは読み取り専用で、JSON を書き出す前に編集可能な FH6 レイヤーテーブルを検証します。
- インポートは通常の JSON 一覧からフルシェイプ/type-code JSON を自動判別します。保存して開き直した白い円だけのテンプレート (通常 3000 レイヤー) を、インポート前にグループ解除して使う前提です。
- 対応するフルシェイプ JSON のマーカー: `type_word`、`shape_word`、FH6 のフル type code、Kloudy/Fabric 形式の手作り JSON のフィールド、フォントシェイプのフィールド、`Circle`・`Square`・`Triangle`・`Ellipse` などの基本シェイプ名。
- type-code JSON のプレビューには同梱の FH6 バイナル頂点リソースを使うため、新しいエクスポーターの複数シェイプ JSON や Kloudy/Fabric 形式の手作り JSON も、長方形で代用せずにプレビューできます。
- マスクレイヤーは、下に描画済みのレイヤーを透明に切り抜く形でプレビューされます。FH6 の UI サムネイルではマスクのシェイプ自体が表示される場合があります。
- フルシェイプのインポート後は、結果を判断する前にバイナルグループを保存して開き直してください。FH6 は現在のエディターで古いテンプレートのリソースを表示し続けることがあります。
- フルシェイプのインポート/エクスポートに失敗すると、FH6・エディター・テンプレートの重要な確認事項が表示されます。`フルシェイプレポートをエクスポート` はデバッグデータを送る必要がある場合のみ使ってください。
- インポーターが書き込むのは安定した表示フィールドと、レイヤーオフセット `0x7A` の 16-bit シェイプワードのみです。
- `0xA8` などの揮発性の FH6 リソースポインターはコピーしません。
- インポート完了後は、UI サムネイルが古いまま見える場合に備え、FH6 のバイナルグループを保存して読み込み直してから判断してください。

## 実験的: 領域ペイント

領域ペイントは繰り返し描き込むワークフローです。まず画像全体にベースレイヤーを生成し、次に矩形または楕円ツールで領域を選択して、その領域だけをレイヤーを追加して仕上げます。

- 画像を 1 枚追加し、品質プロファイル (`stopAt` から総予算が決まる) を選んで、初回パスのレイヤー数と領域レイヤー数を調整します。
- `初回パスを開始` をクリックしてベースレイヤーを生成します。右のキャンバスにプレビューが表示されます。
- 左のキャンバスで矩形または楕円ツールを使って選択領域を描きます。赤いオーバーレイが選択範囲です。
- `除外モード` にチェックを入れると、代わりに除外領域 (半透明の**黒い**オーバーレイ) を描けます。`含める/除外を切替` ボタンで、選択中のシェイプを含める/除外の間で切り替えられます。含める領域と除外領域が重なる場合は除外が優先され、`選択領域をペイント` は除外領域*以外*にレイヤーを生成します。
- `選択領域をペイント` をクリックすると、その領域内にだけレイヤーを追加します。領域ごとに繰り返します。
- すべてのパスが終わったら、`結果フォルダーを開く` または `結果 JSON を保存` で最終的な `base.json` を取得します。
- 結果の JSON は `インポート` タブから、通常の生成と同じ手順でインポートします。
- 残り予算は `残り` の横に表示されます。領域パスごとにこの予算からレイヤーを消費します。

## 重要なルール

- インポート前に FH6 のテンプレートをグループ解除しておく必要があります。
- アプリに入力するレイヤー数はゲーム内と完全に一致させてください。
- インポート中はゲームのメニューを切り替えないでください。
- FH6 の再起動、テンプレートの再読み込み、レイヤー数の変更をした後は、新しい正しいレイヤー数で再度インポートしてください。
- JSON のレイヤー数がテンプレートより少ない場合、使われないテンプレートレイヤーは非表示になります。
- JSON のレイヤー数がテンプレートより多い場合、余ったシェイプは切り捨てられます。
- PNG の透明な背景は、見える背景としてはインポートされません。

## ランタイムファイル

単体 EXE は内部ファイルを一時的に展開し、通常のランタイムデータは EXE の外に保存します。正確なパスは起動時のログに表示されます。

EXE と同じ場所に作成されるフォルダー:

- `runtime/`: ログ、生成セッションのデータ、アプリの一時ファイル。
- `webui-data/`: ローカルのブラウザー/UI キャッシュ。

ローカルのランタイムデータをリセットしたい場合は、アプリを閉じた状態でこれらのフォルダーを削除できます。

## トラブルシューティング

- **EXE から FH6 にインポートできない:** アプリを閉じ、EXE を管理者として実行してください。
- **GPU/OpenCL のエラー:** NVIDIA/AMD/Intel のグラフィックドライバーを更新してください。同梱のジェネレーターは OpenCL を使います。
- **グラフィックカード一覧が空、またはカードが表示されない:** アプリは OpenCL ICD ローダーが報告するカードを一覧表示します。グラフィックドライバーを更新し、`GPU を再検出` をクリックしてください。Intel GPU は一覧には表示されますが、Intel のランタイムがデバイス選択に対応していないため指定はできません。
- **テンプレートが検出されない:** バイナルグループエディターにいること、テンプレートがグループ解除されていること、レイヤー数が正確であること、検出中にメニューを切り替えていないことを確認してください。
- **インポート結果がぼやける:** レイヤー数の多い JSON を使うか、`出力レイヤー数` / `ランダムサンプル数` を上げてください。
- **デバッグの協力が必要:** アプリの `詳細ログをエクスポート` を使い、ログを Issue に添付してください。
